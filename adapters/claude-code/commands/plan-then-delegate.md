Plan for: $ARGUMENTS. Chat: lean STE (tables for numbers). Plan text, commands, code: full.

1. Check the planner model (CLAUDE.md). A code ticket not in its worktree → `python3 ~/.claude/concord/wt.py new <TICKET>` + `EnterWorktree` (`wt.py list` shows OVERLAP / DRIFT).
2. Context: read only until you can name the files and the acceptance commands: `~/.claude/concord/repo-notes/<repo>.md`, the code, the spec or Figma the ticket names, the `Cases:` file that the repo notes name, and the skills that fit; no edits. Leave what you read as `Notes:` pointers: the executor does the deep reading. Trivial task → offer a direct edit, no plan. Cut every item the goal does not need.
3. Early plan: write `PLAN_<ticket>.md` at the repo root from `~/.claude/concord/PLAN_TEMPLATE.md` (never `PLAN.md`; ask before overwriting). If `git check-ignore -q PLAN_<ticket>.md` fails, add `/PLAN_*.md` to `$(git rev-parse --git-common-dir)/info/exclude`. Sections: Design (by workflow stage), Test plan (each touched behavior: KEEP, EXTEND, MERGE, REPLACE, DELETE or ADD; ADD only when no test covers it), Conflicts between sources, Open questions. The head carries `Tests: +A/−D lines, net ≤ N`. Per phase: `Size:` and `After: <phase> (<reason>)`, and no minutes. Plan in passes, not a chain: right after this session's failing tests, pass 1 starts every phase at once, rough; each later pass fixes only the largest gaps the last check found. Only real dependencies wait: a phase waits for the tests it runs, and phases that share a file wait or take forks. Executors as in CLAUDE.md.
4. Lint each delegated phase (no model call): `concord.py --lint <phase> --plan <PLAN> --repo <dir>`. Fix what its ACCEPTANCE LINT and PLAN LINT lines name.
5. Grill: ask the user at most 5 blocking questions in one message, each with the default you take without an answer. Record the answers under `## Settled` and the defaults under `## Defaults taken`.
6. Verify: spawn the `concord:plan-verifier` agent with the plan path and the facts that the plan does not state, on the model that you do not use (`fable` or `opus`). One round; a second only to confirm your fixes. Apply its items or reject one with an owner decision. Save its final answer to a file and record it: `concord.py --plan-verdict <file> --plan <PLAN>`.
7. Estimate: `concord.py --estimate --plan <PLAN>` computes the phase minutes from the run ledger, the lanes, the critical path, the session lane and the ETA, and stores the ETA for the drift gate. Fix its ESTIMATE LINT lines, then copy its PASSES, CRITICAL PATH and ETA lines into `## Passes` (an APPROVE survives edits there).
8. Go/no-go: show the lane diagram, the ETA with the local time it lands, the verifier's cuts and the open items in one message. Stop until the user says go; a partial go covers only those phases.
9. Run the approved phases as `/concord:delegate all` would. Context already large → hand off: write the plan's `## Handoff`, `ExitWorktree keep`, start a fresh planner-model session in the worktree with `/concord:delegate all --plan PLAN_<ticket>.md`, detach it and end this one (none can start → `EnterWorktree` back and run here). A PR ticket ends at the PR gate (`/concord:delegate` §6), then the test report and the KB step (`/concord:delegate` §7).
