description: Run plan phases on their planned executor or on a model the user names ("deepseek flash", "sonnet"), then verify each phase independently and record the verdict
argument-hint: [model] <phase | 1,3 | 2-4 | all> [feedback | escalate]

Delegate phases, verify every result. Arguments: $ARGUMENTS. Chat: terse (tables). Commands, plan text, code: full.
Flags and report fields: `python3 ~/.claude/concord/concord.py --help`. Test suites: `bash ~/.claude/concord/tests/run_all.sh` (outside the sandbox).

## 1. Resolve
- Plan: `PLAN_<ticket>.md` named in the request, else the only plan at repo root; `--plan <file>` on every call. None → offer `/concord:plan-then-delegate`. Never `PLAN.md`.
- Phases: number, list (1,3), range (2-4), `all` (in order). Model: request > phase `Executor:` > models.conf `default` > ask. Names: `concord.py --resolve "<name>"`; unknown/ambiguous → ask, never guess. "via <harness>" → `--via`; other words → `--extra=<text>`.
- Billing: sonnet/haiku/opus only as Claude subagents on the subscription (concord.py enforces); deepseek-flash on Go by default; zen-* = credits → on "usage limit exceeded" stop and ask. `concord:implementer-opus48` (Opus 4.8, effort high): (a) a "subtle logic" phase the planner assigned to it (high risk AND logic-dense: gates, state machines, security checks, untrusted parsers) when OpenCode would do worse, or (b) Go and Zen both unavailable (state the switch in one line). Same contract: `--begin <phase> --label opus` → subagent `concord:implementer-opus48` → `--end last` → verdict.

## 2. Run (one checkout = one run at a time; everything independent in parallel)
- Parallel by default: reviews of the same diff, PR reviews, the next phase's planner work while an executor runs, other tickets in their own worktrees. Ask only for significant risk (CLAUDE.md).
- Every run starts with a red run on the untouched tree. Exit 6 = an acceptance command already passes → TEST_DEFECT, or mark it `(characterization)` when the phase preserves behaviour.
- planner / Claude subagent: `--begin <phase> --label <name>` → work (subagent prompt: plan path, phase, feedback) → `--end <run-id>`. Other executors: Bash run_in_background, outside the sandbox: `concord.py <model> <phase> [--plan F] [--extra=<feedback>]`.
- Read every report line; the ones that fail a phase: OUT OF SCOPE (source), DELETED, STAGED BY EXECUTOR, GIT INTERNALS CHANGED, PLAN FILE MODIFIED, HEAD/BRANCH moved, DEPENDENCIES CHANGED, OVER BUDGET, INTERFACE MISMATCH, CHARACTERIZATION CHANGED, ACCEPTANCE FILES CHANGED (PASS refused, exit 7), OUTSIDE CHECKOUT CHANGED caused by the executor, STATIC NEW defects (F821/F841/F811/B). An `EXECUTOR BLOCKED` line = FAIL BLOCKED, once per phase (§4); an OpenCode refusal of an unlisted file without that line = PLAN_GAP.

## 3. Verify yourself; never trust the executor's report
- Verification is `concord.py --card <run>` (zero tokens: run, phase, risk tier and any floor, acceptance as recorded, scope, `git diff --stat`, reviews, a FLAGS line of the files a checker must open; it also writes a verify packet), then a FRESH `concord:verifier` subagent (Opus 5.5, read-only) on that packet — it re-runs the acceptance commands and reads only the flagged hunks, answering one VERIFY-JSON block. The verifier is NOT the review (independence rules unchanged). Then confirm the verdict from the card and the VERIFY-JSON; do not read the full diff in this session unless a FLAG or the verifier points you to it.
- Re-run acceptance FROM THE REPORT when you check a point yourself. Failing → re-run once; results differ → FAIL FLAKY (fix the test, not the implementer).
- Diff of a flagged hunk: `git diff HEAD -- <changed files>`. FAIL on out-of-scope source, test files touched by an implementing phase, or any blocking report line above.
- Review = an independent fresh agent, never the author; planner-written code gets the same reviewers. Every reviewer answers one REVIEW-JSON block; the dispatcher downgrades BLOCKER/HIGH/MEDIUM without a reproduction to NOTE, filters findings outside the diff, computes the verdict, keeps the ledger (ids F<n>, binding for later reviewers).
- Tiers: low = flash `concord.py --review <run>`; medium = `concord:reviewer-opus48` only; high = `concord:reviewer-opus55` only, plus property tests and `concord.py --mutate <run>` (every SURVIVED mutant answered by a test or a recorded reason). Opus: `--review <run> --packet` → a FRESH Agent each round (never resume one; the ledger carries earlier findings), prompt `Review packet: <path>. Acceptance (planner re-run): <command → result>. Read first: <functions from Context>.` → save its block → `--review-record <run> --reviewer <name> --file <f>`. Opus reviewers run on the Claude subscription only. A PASS below the phase's tier is refused (exit 9; a `Baseline: skip` phase needs flash or better); override only with the user's go-ahead: `--user-approved "<their words>"`. Oversized run diff → `--review <run> --files <globs>` per file group, like PRs; every group reviewed before `--close-round`. A repo-notes line `Risk floor <tier>: <globs>` raises the tier of any run or PR that changes a matching non-test file: a phase PASS below it is refused (exit 9, the refusal names the path); a PR review records the raised tier and prints a note.
- Review reuse (cheaper checking): every clean review (flash `--review`, `--review-record`, and a clean `--review-pr`) stores the git blob of each file it saw and its tier. Any review that would only re-cover files a recorded equal-or-higher-tier review already cleared at the same content prints `COVERED: <n> files already reviewed by <reviewer> (<tier>) ...` and runs no model (it records a reused entry, so the exit 9 tier gate still passes); when only some files changed it reviews just those and names the reused ones. This covers a flash `--review` (tier 1), an Opus `--packet`, and a full `--review-pr` alike (a lower tier never covers a higher one; the delta path is unchanged). A suppressed `--review-pr` records the gate at the fetched head, so `--pr-status` reports it met and names the covering reviews. `--force-review` reviews anyway. `--lint <phase>` prints `LINT SKIPPED: executor <name> is a Claude model` and only the zero-token ACCEPTANCE LINT lines when the phase's `Executor:` is a Claude model (sonnet, haiku, opus, fable or any `concord:implementer*`).
- Confirm every finding against the diff yourself. Confirmed BLOCKER/HIGH → FAIL, fix right away (same executor, structured feedback), re-review the fix (delta). Confirmed MEDIUM → same fix round. The loop stops when only NOTEs remain; NOTEs go to one ledger and one combined fix later. Rounds end on evidence, not budget.
- Close the round in one call: `concord.py --close-round <run> --adopt F1,F3 --wrong "F2=why" --decline "F4=why" [--test "F1=tests/x::t"] --verdict-result PASS|FAIL [--cause EXECUTOR|PLAN_GAP|TEST_DEFECT|FLAKY|PROVIDER|BLOCKED, or SPEC_GAP on a PASS] --note "<why>"` (tokens auto). Review-time decisions/assumptions: `--review-decide <run> --decision "..." [--kind assumption]`.
- PASS only if acceptance passes and the diff matches the phase. Then the next phase.

## 4. FAIL: classify first, then act
- EXECUTOR: retry the same model with `--extra="EVIDENCE: <command + decisive lines> | SUSPECTED: <files> | CHANGE: <what must differ>"`; max 3 attempts (the 4th start is refused, exit 8; same `--user-approved` override); escalate (models.conf `ladder`) only when the user asked.
- SPEC_GAP (amend in place): a review or your own check finds a case the plan never specified, while acceptance is green, scope is clean and the executor followed the plan. Keep the diff: record PASS --cause SPEC_GAP --note "<finding id>: <gap>" (`--close-round`, or `--verdict` when no review round is open); write the missing test yourself; add "## Phase N.1 - <gap> (PN.1 <- S..)" at the parent's heading level with the parent's Executor and Risk, Files, the one Interfaces change, the new test as acceptance and the parent's acceptance as characterization, plus its Work line; run it on the same executor with the finding as `--extra`; its review reads only its own change. The next gap on the same phase is N.2.
- PLAN_GAP: the gap invalidates the design, the scope or the diff, or acceptance fails because the plan was wrong: `--restore <run>`, fix the plan (ask if a decision is needed), retry; not an attempt.
- BLOCKED: the report has an `EXECUTOR BLOCKED: <question>` line. Record FAIL --cause BLOCKED (not an attempt), `--restore <run>` if it changed files, answer in the phase's Decisions (ask the user when the answer is theirs), re-run with `--extra "ANSWERS: ..."`. A second BLOCKED on the same phase is refused: it is a PLAN_GAP.
- Every SPEC_GAP, PLAN_GAP and BLOCKED gets one line in `repo-notes/<repo>.gaps.md`: `- [<class>] <question the plan did not settle> (<ticket>, <YYYY-MM-DD>, found: review|verify|lint|blocked)`. `--lint` asks the open lines in every linted phase of that repository; `PROMOTE <class>` (two lines without a rule) → make it a rule (a `repo-notes/<repo>.md` line, a test, a hook) and add `, rule: <where>` before the closing parenthesis of those lines.
- TEST_DEFECT / FLAKY: the test author fixes the tests; not counted. Out-of-scope edits, deletions, modified plan: stop, show, offer `--restore`.
- New rule from a failure or review: first "general or repo-specific?" (repo → repo-notes / `.gaps.md`), then "which component enforces it?" (code or hook beats prose). Rule budgets and retirement: `/concord:rules-review`.
- Trivial fixes yourself only; say so.

## 5. Report
Per phase: executor + model, billing, risk, PASS/FAIL + cause, acceptance evidence, checks NOT run, review verdict, files changed. End: `concord.py --stats` (rounds per phase, adopted %). Never commit; the user reviews and commits.

## 6. PR gate
- No PR is called ready, mergeable or put in a merge order before a PR review of its full diff (`base...head`; stacked → parent branch) at its tier on its CURRENT head. GitHub MERGEABLE ≠ reviewed. A phase's Opus review counts only when its diff is the PR's diff at that head.
- Tier = riskiest content. high: shipped product code, verdict/score/threshold/licence paths, exporters, untrusted input, security, release config. medium: reference pipelines, data/label/eval pipelines, behaviour-pinning fixtures. low: tooling, scripts, docs. Reviewers: low = flash `--review-pr <PR>`; medium = `concord:reviewer-opus48`; high = `concord:reviewer-opus55` (`--review-pr <PR> --packet` → Agent → `--review-record`). State reviewers + models in one line, do not wait.
- Over the 60k cap → split by file group (`--files`), one reviewer per group, in parallel. After a fix commit: `--review-pr <PR> --delta` (fix diff first + full change of touched files + ledger; a delta over the cap truncates only the context).
- Gate check: `--pr-status <PR>` must print `CURRENT HEAD <sha>: REVIEWED` (directly or via delta); otherwise it names what is open or why a full review is needed. Head moved = unreviewed.
- Own PR + confirmed findings → fix right away, delta review. Others' PR → hand the findings to the author. PR approval = another engineer; never merge.
