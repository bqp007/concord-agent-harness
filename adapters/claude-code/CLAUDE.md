# Default workflow: plan, then delegate

Goal: frontier tokens only for planning and verification; cheap models write the code. Details: the `/concord:plan-then-delegate` and `/concord:delegate` commands, `~/.claude/concord/` (docs: WORKFLOW.md in the Concord repository).

- Any non-trivial code change → `/concord:plan-then-delegate`: targeted reads, a terse `PLAN_<ticket>.md` (phases, exact files, acceptance tests, executor per phase; never `PLAN.md`, it is shared by every session in a clone), stop for approval, then run every phase as `/concord:delegate all` would and verify each independently.
- One ticket = one session = one git worktree: `python3 ~/.claude/concord/wt.py new <TICKET> [--base REF]`, then work there; plan, edits and delegate runs all happen in the worktree. Shared untracked folders (venvs, data) are linked from the main checkout per `worktrees.conf`.
- Never implement code yourself unless trivial (one file, a few lines, context already loaded) or the user says "just do it".
- Executor: `deepseek-flash` (OpenCode Go allowance) by default for every implementing phase; other models only when the user names them; `zen-*` names bill credits → stop and ask first. A failing phase gets up to three attempts with structured feedback (evidence, suspected files, change needed); the fourth is refused by `~/.claude/concord/concord.py` (exit 8). Go and Zen both unavailable → the `concord:implementer-opus48` subagent (Claude subscription), same contract; say so in one line. `concord:implementer-opus48` also takes a "subtle logic" phase (high risk AND logic-dense: gates, state machines, security checks, untrusted parsers) when the plan says why.
- sonnet / haiku / opus run only as the `concord:implementer` subagent on the Claude subscription, never through another harness; `concord.py` enforces this.
- Verify from evidence, never from the executor's own claims: `concord.py --card <run>` (one screen + verify packet), then the `concord:verifier` subagent on the packet in a fresh context; the planner confirms from the card and its VERIFY-JSON and opens diff hunks only where a FLAG points; FAIL on out-of-scope edits or a modified plan. Review tiers: low = flash (`concord.py --review`), medium = `concord:reviewer-opus48` only, high = `concord:reviewer-opus55` only; every reviewer answers one REVIEW-JSON block; confirm every finding yourself; close each round with `concord.py --close-round` (adjudication + verdict). A PASS below the tier is refused (exit 9).
- Parallel by default: independent work (reviews of the same diff, PR reviews, tickets in their own worktrees) runs at the same time; one run at a time per checkout. A confirmed review finding during a workflow is fixed right away. Ask only for significant risk: irreversible or destructive actions, merges, publishing, spending outside the subscription and the Go allowance, or changing an owner decision, product behaviour or an eval set.
- Review = an independent agent with a fresh context that did not write the code. The author never reviews its own code; the session that planned or wrote it only confirms findings.
- PR gate: no PR, own or others', is called ready, mergeable or put in a merge order before a PR review of its full diff at its risk tier on its current head (`concord.py --review-pr`, `--pr-status`). "Mergeable" on the hosting site is not a review.
- Planner model: planning, test writing and verification run in this session on the strongest model available at high effort; a session on less → say so and ask before planning.
- Tests first, written by the planner, never by the implementer; the implementer never edits test files. Acceptance must fail on the untouched code before an implementing phase (red run, checked by `concord.py`) unless the phase preserves behaviour, which then needs a before/after characterization.
- Every FAIL verdict gets a cause: EXECUTOR, PLAN_GAP, TEST_DEFECT or FLAKY. Only EXECUTOR failures count as attempts; plan gaps and test defects are fixed at the plan or the tests.
- Executors cannot ask questions: every ambiguity goes under "Open questions" in the plan and is settled by the user before approval.
- Never commit; the user reviews the diff and commits.
- Token economy: auto-compact at a 400k window (`modelSettings.<model-id>.autoCompactWindow` in `~/.claude/settings.json`, see `settings.snippet.json`); after a compaction re-read the ticket's `PLAN_<ticket>.md` Outcome and Handoff blocks. Chat and agent prose: terse. Plan files, docs, commands, code, commit and PR text: full prose.
- No bloat: every change to this file, the commands or Concord's files carries a line budget; `/concord:rules-review` retires rules that produced no change in a month.
