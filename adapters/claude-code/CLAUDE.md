# Default workflow: plan, then execute or delegate

Goal: reviewed, correct code by the shortest path. This session plans, has the failing tests written first where they buy evidence, writes what costs less to write than to specify and checks every result; cheap models write the bulky code. Details: `/concord:run`, the `concord:*` skills, `~/.claude/concord/`.

- Four outcomes hold firm; within the approved scope the decomposition, the executors and the order are this session's call. Governance: the owner settles every consequential behavior or architecture choice whatever the size of the change (the `concord:design-review` skill says which choices are consequential), and review judges the design that was approved. Testing: every changed behavior and path is accounted for; a test stays when it catches a failure the rest of the suite would miss where it matters; testing stops when that evidence suffices (`concord:lean-testing`). Code quality: an independent reviewer examines each consequential change, its affected callers included (`concord:review-change`); an explicit design failure stays visible until it is resolved. Truthful outcomes: PASS and REVIEWED mean what they say, a waiver names its scope, and recovery keeps user work.
- Non-trivial change → `/concord:run execute <task>` (this session writes every phase) or `/concord:run delegate <task>` (phases go to their executors; the default when the owner names no mode): plan, grill, an independent verifier's APPROVE of the exact plan text, one go/no-go, implement, check, review, report. A routine or trivial change takes a direct edit and its focused check. `/concord:plan`, `/concord:verify-plan`, `/concord:design-review`, `/concord:lean-testing` and `/concord:review-change` also work on their own.
- Parallel by default: independent tickets, reviews and background runs at the same time; one writer per file (the run lock covers each phase's `Files:` and `Follow-through:`). Ask only for significant risk: irreversible or destructive actions, merges, publishing, outward writes not yet approved, spending beyond the free tiers, or changing an owner decision, product behaviour or an eval set.
- Agent names: Concord's agents are spawned as `reviewer-opus55`, `reviewer-delta`, `plan-verifier`, `implementer-opus48` and `implementer` (symlinks in `~/.claude/agents`).
- Planner: the strongest model available, at high effort; else say so and ask before planning.
- Never commit; the user reviews the diff and commits.
- Tokens: an auto-compact window per session model (`modelSettings.<model-id>.autoCompactWindow` in `~/.claude/settings.json`); after a compaction re-read the ticket's plan. Chat and agent prose follow `~/.claude/concord/style.conf` (lean STE by default). Plans, docs, commands, code, commit and PR text: full prose.
