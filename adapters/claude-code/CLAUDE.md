# Default workflow: plan, then delegate

Goal: reviewed, correct code by the shortest path. This session plans, writes the tests and the small changes, and checks results; free models write bulky code. Details: `/concord:plan-then-delegate`, `/concord:delegate`, `~/.claude/concord/`.

- Non-trivial change → `/concord:plan-then-delegate`: a one-page `PLAN_<ticket>.md` (per phase: executor, risk, files, steps, acceptance commands; never `PLAN.md`), open questions settled by the user, stop for approval, then run it as `/concord:delegate all` would (here, or in a fresh session when this one's context is large).
- One ticket = one git worktree: `python3 ~/.claude/concord/wt.py new <TICKET> [--base REF]` from the main checkout, then `EnterWorktree`; write outputs inside it. Ticket end, after the user committed and pushed: `ExitWorktree keep`, then `wt.py done <TICKET>` outside the sandbox.
- Who writes code: this session for changes up to about 60 lines, for code it already wrote while testing, and for docs; a free model for bulky, well-specified work: `free-deepseek-flash`, then `free-glm-flash` (OpenCode Zen free tier), then `deepseek-flash` (Go allowance); all out → `concord:implementer-opus48`, said in one line. Paid `zen-*` only after asking. sonnet/haiku/opus only as the `concord:implementer` subagent (`~/.claude/concord/concord.py` enforces this).
- Tests first, by this session; implementers never edit tests. A delegated phase's acceptance must fail on the untouched code (red run) unless marked `(characterization)`.
- Check a delegated phase yourself: the dispatcher's blocking report lines, the acceptance commands re-run here, `git diff` of its files. A FAIL records its cause (EXECUTOR, PLAN_GAP, TEST_DEFECT, FLAKY, PROVIDER, BLOCKED); only EXECUTOR counts: three attempts with feedback (evidence, files, change needed), then ask. An executor that meets an unsettled question stops once with BLOCKED.
- Review once, by an independent agent that did not write the code: low = flash (`concord.py --review`, `--review-pr`), medium and high = `concord:reviewer-opus55` (Claude subscription; say so in one line). A ticket that ships by PR is reviewed at the PR gate: its full diff at its tier on its current head, until `concord.py --pr-status` prints REVIEWED; no PR, own or others', is called ready, mergeable or put in a merge order before that (GitHub "mergeable" is not a review). Otherwise review each implementing phase once. Fix confirmed BLOCKER/HIGH/MEDIUM findings right away (confirm by reading the cited lines) and re-review the fix once (delta); still open after two fix rounds → ask. NOTE findings go in the report.
- Parallel by default: independent tickets, reviews and background runs at the same time; one writer per checkout. Ask only for significant risk: irreversible or destructive actions, merges, publishing, outward writes not yet approved, spending beyond the subscriptions and the free tier, or changing an owner decision, product behaviour or an eval set.
- Planner: this session on the strongest model available, at high effort; anything less → say so and ask before planning.
- Never commit; the user reviews the diff and commits.
- Tokens: auto-compact at a 400k window (`settings.snippet.json`); after a compaction re-read the ticket's plan. Chat and agent prose: terse. Plans, docs, commands, code, commit and PR text: full prose.
